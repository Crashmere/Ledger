## 已确认的产品与实现边界

- 单人账本，无登录，联网才能查看和记账；用户接受知道地址的人可以查看和修改。当前使用公网 HTTP、`/ledger/` 子路径；这不是对其他应用的默认访问授权。
- 服务器保存唯一正式数据。前端 Vue，后端 Go + SQLite；较重的统计/计算与业务校验在后端，前端保留显示与轻量计算。
- 交易分页，筛选和统计 API 尽量通用，以便以后合并冗余页面。保持直接可读的代码，不为假想并发扩展复杂层次。
- 删除用 `is_delete`，网页无回收站。金额整数分，账目日期按北京时间，底层时间保留 epoch 毫秒。
- 没有浏览器账本、GitHub 数据同步、离线写队列或 Service Worker。浏览器只保存显示偏好、近期搜索等非账本状态。
- 网页无 SQL 控制台、导出、恢复或迁移入口，无独立设置页；相关轻量选项回到对应页面。备份恢复只由服务器维护工具处理。
- 服务器数据库是唯一正式账本，重建使用 Ledger 一致性备份或明确创建空库；不从其他快照覆盖现账本。GitHub 仅用于源码和 CI/CD，Pages 未启用。
- 手机使用原生金额输入，电脑保留计算器；manifest 仅用于桌面入口，不代表支持离线。HTTP/iOS 安装行为有平台限制，不承诺强制隐藏浏览器工具栏。
- 手机搜索入口位于底部导航，顶栏不重复提供搜索按钮；电脑搜索入口位于侧栏。
- 手机新建和编辑交易的日期独占一行，直接使用系统日期选择器，前后一天按钮与日期输入组成一组；标签另起一行，避免日期浮层遮挡其他字段。
- 手机和电脑切页立即更新标题和导航；页面代码、初始数据未就绪时显示骨架屏，读取失败显示错误和重试入口。
- 新增、编辑和批量记账都等待服务器确认；保存期间显示模态加载界面、阻止站内离开和重复点击，成功后才清空或返回。失败保留表单，结果不明时先核对账目，当前表单不重复提交。

## 维护与改进

这些是当前约定，不是禁止改进。新需求可调整架构，但应说明收益、数据/发布影响和迁移方式；影响其他应用时按共享技能评估全部项目。修改公网暴露、权限、恢复时点或跨项目停机需要用户确认。

维护结束前核对：实现与测试、对应 docs、部署源文件、共享清单（若受影响）、Git 同步、服务器文档副本。文档与运行程序分别版本化；`/opt/ledger/docs/SOURCE` 说明文档来源，`/opt/ledger/current-commit` 说明程序来源，二者允许不同但不能混淆。
